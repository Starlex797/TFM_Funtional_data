1. Objetivo del proyecto

El proyecto propone una metodologia de fusion espacio-temporal para combinar dos tipos de datos ambientales que tienen distinta naturaleza espacial:

Datos in situ

Mediciones puntuales tomadas en localizaciones concretas del lago. Son observaciones precisas pero espacialmente escasas.

Datos satelitales

Observaciones remotas sobre una rejilla o celdas espaciales. Cubren mas territorio, pero son areales y pueden tener sesgos o valores perdidos.

Fusion

El modelo combina ambas fuentes en un unico campo latente espacio-temporal para aprovechar la precision puntual y la cobertura espacial.

La aplicacion real se centra en floraciones algales en el Western Basin del lago Erie, usando clorofila como variable principal. La variable de trabajo es log_chla, es decir, el logaritmo de la concentracion de clorofila.

4. Flujo paso a paso

Definir region y periodo

En el analisis real se usa el periodo identificado como 20140515_20160514_8235, con ndays = 730. La region se limita al Western Basin del lago Erie mediante rangos de latitud y longitud.

Preprocesar datos satelitales

satellite_preprocess() lee archivos NetCDF, recorta la region, conserva las celdas con informacion valida y construye una tabla larga con fecha, celda espacial, coordenadas y log_chla.

Emparejar datos in situ y satelite

match_up() busca, para cada observacion in situ, la celda satelital mas cercana en la misma fecha. Esto permite comparar ambas fuentes y estudiar diferencias o sesgos.

Integrar ambas fuentes

integrate_data() asigna cada medicion in situ a una celda de la rejilla satelital, filtra muestras de superficie, elimina duplicados por fecha-celda y construye una tabla conjunta. La variable cat distingue satelite (cat = 1) e in situ (cat = 2).

Crear poligonos areales

create_polygon() transforma la rejilla satelital en poligonos. Esto es clave porque el satelite no se modela como punto exacto, sino como una observacion areal asociada a una celda.

Construir la malla SPDE

El script crea una malla triangular con inla.mesh.2d(). Sobre esa malla se define un campo gaussiano Matern aproximado con SPDE.

Construir matrices de proyeccion

Para los datos in situ se usa una matriz Apt que proyecta el campo desde la malla a puntos concretos. Para satelite se usa una matriz areal Aat, construida con bloques y reescalado por suma, que conecta el campo latente con celdas/poligonos.

Montar los stacks de INLA

Se crean stacks separados: stk.pt para puntos in situ y stk.at para observaciones areales satelitales. En el modelo fusionado ambos se combinan en stk.full.t.

Ajustar tres modelos

El proyecto compara: modelo solo in situ, modelo solo satelital y modelo de fusion. Los tres usan INLA-SPDE con estructura temporal AR(1).

Evaluar resultados

Se extraen efectos fijos, hiperparametros, kappa, varianza, parametros temporales, DIC, log marginal likelihood y RMSE predictivo. En simulacion tambien se compara contra parametros verdaderos.

5. Modelo estadistico

El modelo asume que existe un campo latente espacio-temporal comun que representa la concentracion real de clorofila. Las distintas fuentes observan ese campo con distinto soporte espacial y distinto error.

y(s,t) = beta0 + beta1 * lon(s) + beta2 * lat(s) + covariables(t) + w(s,t) + error

En el analisis real, la formula de fusion incluye:

y ~ 0 + intercept + a + beta1 + beta2 + wind_speed + air_temp + surface_temp + f(s, model = spde, group = s.group, control.group = list(model = "ar1"))

Donde:

  • intercept es el nivel medio del proceso.
  • a representa un efecto especifico de la fuente satelital, interpretable como sesgo o diferencia entre soporte/fuente.
  • beta1 y beta2 capturan tendencia espacial con longitud y latitud centradas.
  • wind_speed, air_temp y surface_temp son covariables ambientales.
  • w(s,t) es el campo latente Matern aproximado por SPDE.
  • AR(1) introduce dependencia temporal entre dias consecutivos.

6. Que solucion propone

La solucion principal es tratar la fusion de datos como un problema de inferencia sobre un campo latente comun. En vez de elegir entre satelite o in situ, el modelo usa ambas fuentes de forma conjunta.

Corrige el problema de soporte espacial

Los datos in situ son puntuales y los satelitales son areales. El proyecto usa matrices de proyeccion diferentes para cada soporte.

Aprovecha fuentes complementarias

El satelite aporta cobertura espacial y temporal; el in situ aporta mediciones directas.

Modela dependencia espacio-temporal

SPDE captura continuidad espacial y AR(1) captura persistencia temporal.

Cuantifica incertidumbre

INLA produce distribuciones posteriores para parametros, campo latente e hiperparametros.

7. Estudio de simulacion

La carpeta Proyecto_Wuong incluye una simulacion para validar el metodo bajo escenarios controlados. Primero rspde_fn.R genera un campo espacio-temporal artificial con parametros conocidos:

intercept = 2 bias = 0.25 beta = (-1, -1) rho = 0.7 kappa = 7 variance = 0.25

Despues se generan dos tipos de observaciones:

  • Satelitales/areales: observan promedios sobre poligonos, con sesgo y ruido.
  • In situ/puntuales: observan puntos concretos del campo, con otro nivel de ruido.

simulation.R prueba distintos escenarios variando:

  • resolucion de malla: max.edge = 0.15, 0.1, 0.05;
  • numero de puntos in situ por tiempo: 5 o 30;
  • porcentaje de datos satelitales perdidos: 0.5 o 0.8;
  • comparacion entre modelos in situ, satelite y fusion.

simulation_plot.R resume los resultados en graficos de sesgo, RMSE de parametros, RMSE predictivo y tiempo de computo. La idea es demostrar que la fusion puede mejorar la estimacion y prediccion frente a usar solo una fuente.

8. Analisis real

real_data.R aplica la metodologia al caso real del lago Erie. El flujo es:

  • carga datos preprocesados de satelite e in situ desde un objeto .rda;
  • carga covariables ambientales diarias: viento, temperatura del aire y temperatura superficial;
  • define la malla SPDE sobre las coordenadas del dominio;
  • crea poligonos para el soporte areal del satelite;
  • construye matrices A para observaciones puntuales y areales;
  • ajusta un modelo fusionado con dos familias gaussianas, una para cada fuente;
  • ajusta tambien modelos separados: solo satelite y solo in situ;
  • guarda objetos mod_fusion_spde_ar1.rda, mod_satellite_spde_ar1.rda y mod_insitu_spde_ar1.rda.

La comparacion entre estos modelos permite evaluar si la fusion aporta ventaja frente a analizar cada fuente por separado.

9. Relacion con tu TFM

Este proyecto es muy util para tu TFM porque trabaja con la misma familia metodologica que quieres usar: modelos bayesianos espacio-temporales con INLA-SPDE. La diferencia principal es el tipo de datos:

stfusion-main Tu TFM NO2
Fusiona datos in situ y satelitales. Fusionas/relacionas estaciones de NO2 con clima, trafico y espacio urbano.
Variable respuesta: log_chla. Variable respuesta: log(NO2 + 1).
Problema de soporte: punto frente a area. Problema parecido: estaciones puntuales frente a covariables agregadas por barrio/distrito o interpoladas.
SPDE + AR(1) para campo latente de clorofila. SPDE + AR(1) para estructura residual espacial/temporal del NO2.

La idea teorica que puedes trasladar es: cuando las fuentes de informacion no tienen el mismo soporte espacial, conviene construir un modelo comun con matrices de proyeccion adecuadas para cada fuente.

10. Esquema para explicar en memoria

  1. El repositorio aborda la fusion espacio-temporal de fuentes ambientales heterogeneas.
  2. Parte de una variable ambiental observada con dos soportes: mediciones puntuales in situ y datos satelitales areales.
  3. Construye un campo latente comun que representa el proceso real no observado.
  4. Usa SPDE para aproximar un campo gaussiano Matern en una malla triangular.
  5. Usa AR(1) para representar dependencia temporal.
  6. Usa INLA para realizar inferencia bayesiana eficiente.
  7. Compara modelos separados y modelo fusionado.
  8. Valida el enfoque mediante simulaciones y una aplicacion real al lago Erie.

11. Limitaciones de esta copia

  • Hay rutas absolutas o relativas propias del entorno original de los autores.
  • El script real espera archivos .rda y NetCDF que no aparecen con la misma organizacion local.
  • El archivo de salida disponible muestra errores porque no se encontro INLA o porque las rutas de datos no coincidian.
  • Para ejecutar el proyecto habria que corregir rutas, cargar INLA correctamente y asegurar que los archivos satelitales NetCDF estan disponibles.
